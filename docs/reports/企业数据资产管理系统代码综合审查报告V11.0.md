## 一、项目概述

### 1.1 系统架构

EDAMS采用微服务架构设计，主要包括：

| 层级 | 组件 | 技术栈 |
|------|------|--------|
| 前端 | Web应用 | React 18 + TypeScript + Ant Design |
| 网关 | API Gateway | Spring Cloud Gateway |
| 核心服务 | 元数据、血缘、质量、治理等 | Spring Boot 3.x |
| 支撑服务 | Nacos、Kafka、Redis、Neo4j | 多种中间件 |
| 存储层 | MySQL、Elasticsearch、Neo4j | 多模态存储 |

### 2.2 代码Bug发现

#### 🔴 高优先级Bug

**1. ChatServiceImpl.java - 硬编码租户ID**
```java
// 位置: ChatServiceImpl.java:107, 127
.tenantId(1L)  // 硬编码租户ID，不应写死
```
**影响**: 多租户场景下数据隔离失效
**建议**: 从安全上下文获取租户ID

**2. IntentRecognizerImpl.java - 意图识别精度不足**
```java
// 位置: IntentRecognizerImpl.java:67
BigDecimal confidence = BigDecimal.valueOf(matchCount * 0.2).min(BigDecimal.ONE);
```
**影响**: 简单关键词匹配无法处理复杂语义
**建议**: 集成LLM进行语义理解

**3. ResponseGeneratorImpl.java - 响应数据为Mock**
```java
// 位置: ResponseGeneratorImpl.java:215-226
资产名称：%s
资产类型：数据表
所属数据库：edams_prod  // 硬编码mock数据
```
**影响**: 实际使用无法获取真实数据
**建议**: 调用元数据服务获取真实数据

#### 🟡 中优先级问题

**4. QualityRuleController.java - 响应格式不统一**
```java
// 部分接口返回 wrapResponse，部分直接返回数据
return ResponseEntity.status(HttpStatus.CREATED).body(wrapResponse(response));
// vs
return ResponseEntity.ok(lineageService.queryLineageGraph(request));
```
**影响**: 前端需要处理多种响应格式
**建议**: 统一使用wrapResponse包装

**5. LineageController.java - compare接口未实现**
```java
// 位置: LineageController.java:164-172
return ResponseEntity.ok(Map.of(
    "assetId", assetId,
    "version1", version1,
    "version2", version2,
    "addedRelations", List.of(),  // 空实现
    "removedRelations", List.of()  // 空实现
));
```
**影响**: 血缘对比功能不可用
**建议**: 实现快照对比逻辑

**6. GovernanceTaskController.java - 缺少执行记录**
```java
// executeTask只返回executionId，无状态追踪
return ResponseEntity.ok(Map.of(
    "executionId", executionId,
    "message", "任务已开始执行"
));
```
**影响**: 无法查询任务执行状态
**建议**: 添加状态查询接口

### 3.2 发现问题

#### 🟡 问题1: Rules.tsx 启用/禁用接口调用错误

```typescript
// 位置: QualityRules.tsx:158, 169
// 错误: 使用PUT方法
await http.put(`${API_PATHS.QUALITY.RULES.ENABLE(String(id))}`);

// 正确: 应使用POST方法
// API契约定义的是 POST /api/v1/quality/rules/{id}/enable
```

**影响**: 功能不可用
**建议**: 修改为 `http.post()`

#### 🟡 问题2: Rules.tsx 执行规则接口参数错误

```typescript
// 位置: QualityRules.tsx:180
await http.post(API_PATHS.QUALITY.CHECK.TRIGGER, { ruleId: record.id });

// 根据API契约，应传 assetId 而非 ruleId
await http.post(API_PATHS.QUALITY.CHECK.TRIGGER, { assetId: record.id });
```

**影响**: 规则执行失败
**建议**: 确认API契约并修正参数

#### 🟡 问题3: 异常处理不完善

```typescript
// 位置: Rules.tsx:88-90
} catch (error) {
  message.error('加载规则列表失败');
  console.error('加载规则列表失败:', error);
}
```

**问题**: 只记录日志，未向用户展示详细错误信息
**建议**: 从error对象提取具体错误信息
