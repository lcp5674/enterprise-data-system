## 1. 功能概述

### 1.1 核心功能

智能数据分析引擎是一个基于本地大模型的自动化数据治理系统，能够：

1. **数据库扫描**：连接已配置的数据源，自动读取表结构、字段定义、数据样本
2. **智能分析**：调用本地大模型分析表的业务含义、字段血缘、潜在指标
3. **自动化注入**：将分析结果自动注册到元数据、血缘、指标等管理系统
4. **任务管理**：支持异步执行、分批处理、定时任务等多种执行模式

### 1.2 支持的数据源类型

系统支持所有已在 EDAMS 中配置的数据源，包括：
- **关系型数据库**：MySQL、PostgreSQL、Oracle、SQL Server
- **OLAP 数据库**：ClickHouse、Doris、StarRocks、Presto
- **NoSQL 数据库**：MongoDB、Elasticsearch（通过扩展接口）

### 1.3 生成的元数据内容

| 类别 | 内容 | 注入目标服务 |
|------|------|-------------|
| **表结构分析** | 表业务含义、字段注释、数据特征 | MetadataService |
| **血缘关系** | 表间血缘、字段级血缘、ETL血缘 | LineageService |
| **指标定义** | 原子指标、派生指标、计算指标 | IndicatorService |
| **主题域** | 业务主题分类、主题归属 | SubjectDomainService |
| **指标分层** | 指标层级（原子/派生/计算） | IndicatorService |

## 6. 执行流程

### 6.1 任务执行主流程

```java
@Transactional
public void executeTask(Long taskId) {
    // 1. 加载任务配置
    AnalysisTask task = loadTask(taskId);
    if (task == null) throw new TaskNotFoundException(taskId);
    
    // 2. 更新任务状态为RUNNING
    updateTaskStatus(taskId, TaskStatus.RUNNING);
    
    // 3. 获取数据源连接
    DatasourceConfig datasource = getDatasource(task.getDatasourceId());
    
    // 4. 获取模型配置
    LocalModelConfig modelConfig = getModelConfig(task.getModelConfigId());
    
    // 5. 扫描目标表
    List<String> targetTables = scanTargetTables(task, datasource);
    
    // 6. 分批处理
    List<List<String>> batches = partition(targetTables, task.getBatchSize());
    task.setTotalBatches(batches.size());
    
    for (int i = 0; i < batches.size(); i++) {
        if (isTaskCancelled(taskId)) break;
        if (isTaskPaused(taskId)) {
            pauseExecution(taskId);
            return;
        }
        
        List<String> batch = batches.get(i);
        executeBatch(task, batch, i + 1);
        
        updateProgress(taskId, (i + 1) * 100 / batches.size());
    }
    
    // 7. 完成处理
    completeTask(taskId);
}

private void executeBatch(AnalysisTask task, List<String> tables, int batchNumber) {
    // 1. 扫描表结构
    for (String table : tables) {
        TableMetadata metadata = scanTableMetadata(datasource, schema, table);
        AnalysisContext context = buildContext(task);
        
        // 2. 调用LLM分析
        AnalysisResult result = analyzer.analyzeTable(context, table, metadata);
        
        // 3. 自动注册（如配置）
        if (task.getAutoRegister()) {
            registerToSystem(result);
        }
        
        // 4. 保存结果
        saveResult(task.getId(), result, batchNumber);
    }
}
```

### 6.2 定时任务调度

```java
@Scheduled(cron = "${analysis.schedule.cron:0 * * * * ?}")
public void scheduleTasks() {
    // 1. 查询待执行的定时任务
    List<AnalysisTask> tasks = findScheduledTasksReadyToRun();
    
    for (AnalysisTask task : tasks) {
        // 2. 检查是否满足执行条件
        if (canExecute(task)) {
            // 3. 异步执行
            executeTaskAsync(task.getId());
        }
    }
}

private boolean canExecute(AnalysisTask task) {
    // 检查任务状态
    if (task.getStatus() != TaskStatus.PENDING) return false;
    if (task.getExecutionMode() != ExecutionMode.SCHEDULED) return false;
    
    // 检查定时表达式
    if (task.getCronExpression() == null) return false;
    
    // 检查最近是否已执行（防止重复）
    if (wasRecentlyExecuted(task)) return false;
    
    return true;
}
```

## 12. 风险与注意事项

### 12.1 已知限制

1. **Token限制**：大模型有上下文窗口限制，过大的表结构可能需要分块处理
2. **响应稳定性**：LLM输出为JSON格式，可能存在解析失败的情况，需要容错处理
3. **准确性**：LLM分析结果可能存在偏差，需要人工审核
4. **性能**：大量表分析时，LLM调用可能较慢，需要分批和异步处理

### 12.2 优化建议

1. **缓存**：对相同的表结构分析结果进行缓存，避免重复调用LLM
2. **限流**：对LLM API调用进行限流，防止服务过载
3. **重试**：对LLM调用失败进行自动重试
4. **审核**：对自动生成的内容进行人工审核后再注册到系统
